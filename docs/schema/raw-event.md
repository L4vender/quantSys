# Raw Event Schema

Phase 5 archives external raw events from Phase 3 and Phase 4. It does not normalize quotes, map events, produce signals, evaluate risk, create paper fills, sign orders, or call Polymarket order endpoints.

## RawMessage

`RawMessage` is the internal event consumed from `raw.therundown`, `raw.polymarket.market`, and `raw.polymarket.user`.

| Field | Meaning |
|---|---|
| `raw_id` | Deterministic idempotency key. |
| `provider` | `therundown` or `polymarket`. |
| `source_channel` | `rest_bootstrap`, `rest_delta`, `rest_discovery`, `ws_market`, `ws_user`, `rest_geoblock`, `rest_time`, or `rest_clob`. |
| `topic` | Eventbus topic; stored in the archive index. |
| `provider_message_id` | Provider message id when present. |
| `provider_event_id` | Provider event or condition id when present. |
| `provider_market_id` | Provider market, asset, token, or line id when present. |
| `received_at` / `received_mono_ns` | Wall-clock and monotonic ingest time from the adapter. |
| `payload_hash` | Canonical JSON SHA-256 of `payload`. |
| `raw_ref` | Object archive key after Phase 5 archive. |
| `schema_version` | Adapter schema string. |
| `trace_id` | Trace id generated by the adapter. |
| `payload` | External JSON payload, only archived after secret scan passes. |
| `quality_flags` | Raw quality markers, not trading signals. |
| `archive_status` | `received`, `archived`, `duplicate`, `dlq`, or `rejected`. |

## Deterministic IDs

`payload_hash = sha256(canonical_json(payload))`, with object keys sorted recursively before hashing.

`raw_id = provider:source_channel:provider_event_id_or_unknown:provider_market_id_or_unknown:provider_message_id_or_unknown:payload_hash_without_prefix`.

Timestamps, offsets, trace ids, and archive paths are not part of `raw_id`.

## raw_ref And Object Keys

Raw object keys use:

```text
raw/{provider}/{source_channel}/{yyyy}/{mm}/{dd}/{hh}/{raw_id}.json
```

DLQ object keys use:

```text
dlq/{provider}/{source_channel}/{yyyy}/{mm}/{dd}/{hh}/{raw_id_or_payload_hash}.json
```

Keys are sanitized and must not contain secret-like substrings.

## Archive Index

PostgreSQL table: `archive.raw_archive_index`.

Important columns: `raw_id`, `provider`, `topic`, `source_channel`, provider ids, `payload_hash`, `raw_ref`, `schema_version`, `trace_id`, `received_at`, `archived_at`, `archive_status`, `payload_size_bytes`, `quality_flags`, `duplicate_count`, `last_seen_at`, `created_at`, `updated_at`.

`raw_id` is primary key. `raw_ref` is unique. Provider/time, payload hash, provider event id, provider market id, trace id, and topic/channel/time are indexed. Full raw payload is not stored in PostgreSQL.

## DLQ

PostgreSQL table: `archive.dlq_events`.

Fields include `dlq_id`, `raw_id`, `provider`, `topic`, `source_channel`, `error_code`, `error_message`, `error_category`, `payload_hash`, `raw_ref`, `dlq_ref`, `trace_id`, `received_at`, `failed_at`, `retryable`, and `replay_metadata`.

DLQ causes include malformed JSON, missing required fields, blocking unknown schemas, object archive write failure, archive index failure, secret scan failure, invalid topic envelope, provider/channel mismatch, payload hash mismatch, and raw id mismatch.

## Topic Mapping

| Topic | Provider | Channels |
|---|---|---|
| `raw.therundown` | `therundown` | `rest_bootstrap`, `rest_delta`, `ws_market` |
| `raw.polymarket.market` | `polymarket` | `rest_discovery`, `ws_market`, `rest_geoblock`, `rest_time`, `rest_clob` |
| `raw.polymarket.user` | `polymarket` | `ws_user` |

## Secret Policy

Payloads are scanned before archive. Non-redacted values under keys such as `apiKey`, `secret`, `passphrase`, `signature`, `private_key`, `authorization`, or `X-TheRundown-Key` are rejected to DLQ. Error messages are redacted and large payloads are not logged.

## Replay And Audit

Use `raw_id` or `raw_ref` to locate metadata in `archive.raw_archive_index`. Read the payload only through the object archive by `raw_ref`. DLQ rows keep enough metadata for future replay without storing full payload in PostgreSQL.
